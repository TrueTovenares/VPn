# AWG Router — VPN-роутер на Raspberry Pi 4 с веб-панелью

Комплект документации и артефактов для воспроизведения домашнего VPN-роутера
на **Raspberry Pi 4 / Debian 13 (trixie)** с **AmneziaWG** (WireGuard-совместимый
протокол с обфускацией) и собственной веб-панелью управления.

Проект решает две задачи:

1. **VPN-сервер для клиентов** — телефоны и ноутбуки подключаются к `awg0`
   и выходят в интернет через upstream-туннель `awg1`.
2. **Split-routing по России** — адреса из RU-списка идут напрямую через
   домашний роутер, весь остальной трафик — через VPN-провайдера.

Панель позволяет создавать/удалять/переименовывать клиентов, выдавать QR-коды
и конфиги, перезапускать интерфейсы, обновлять RU-маршруты и править upstream.

> **Происхождение.** Документация и текущая версия кода/скриптов подготовлены
> с помощью ИИ-ассистента (OpenCode, DeepSeek V4.1 Flash Free). Подробности —
> в [AI_DISCLOSURE.md](AI_DISCLOSURE.md). Все изменения проверены на живом
> роутере.

## Архитектура

```
            LAN 192.168.89.0/24
                    │
   ┌────────────────┼─────────────────┐
   │                │                 │
[телефон]       [ноутбук]         [другие]
   │                │
   └─────── awg0 (UDP 51820, 10.8.0.0/24) ───────┐
                                                 │
                                   Raspberry Pi 4 (192.168.89.245)
                                   ├── eth0 → 192.168.89.1 → Интернет
                                   └── awg1 (10.71.107.82/32) → VPN-провайдер
```

Маршрутизация клиентов:

| Что | Куда |
|---|---|
| RU-адреса (таблица `100`, имя `awg_foreign`) | `via 192.168.89.1 dev eth0` — напрямую |
| Всё остальное (`default` в таблице `100`) | `dev awg1` — через VPN |
| Правило выбора таблицы | `ip rule from 10.8.0.0/24 lookup awg_foreign priority 400` |
| NAT | `MASQUERADE` для `10.8.0.0/24` в `eth0` и `awg1` |
| MSS | `TCPMSS --set-mss 1240` на `awg1` (защита от фрагментации) |

| Кэши панели | `/var/lib/awg-web/` | последний внешний IP, MAC пиров |

## Быстрый старт

1. Прочитайте `docs/INSTALL.md` и выполните шаги 1–10 на чистой системе.
2. Скопируйте `panel/app.py` и юнит, задайте пароль и сертификат.
3. Проверьте здоровье: `sudo bash scripts/verify.sh`.
4. Создайте первого клиента в панели, скачайте QR или ZIP с двумя конфигами.

Обновление панели после правок:

```bash
sudo bash scripts/deploy-panel.sh panel/app.py
```

## Возможности панели

- HTTP Basic Auth, CSRF-токен на всех POST, rate-limit `10` неудачных попыток
  за `600` секунд на IP (ответ `429` + `Retry-After`). Служебные иконки
  (`/favicon.ico`, `/apple-touch-icon*`) отдаются без авторизации, чтобы iOS
  Safari не показывал второе окно пароля после входа.
- Дашборд: карточки `awg0`/`awg1` (состояние, порт, пиры, handshake, трафик,
  uptime), карточка RU-маршрутов, таблица клиентов.
- Handshake: зелёный ≤ 180 с, оранжевый ≤ 24 ч, красный > 24 ч, серый «нет».
- Создание клиента: ключи `awg`, IP из `10.8.0.0/24`, два конфига
  (внешний и локальный endpoint; локальный всегда указывает на LAN-адрес,
  адреса туннелей `awg0`/`awg1` исключаются).
- Переименование, удаление, перезапуск `awg0`/`awg1`, перезагрузка RPi.
- QR-страница с двумя кодами и ZIP с двумя конфигами.
- Редактор `awg1.conf` с проверкой `awg-quick strip`, автодобавлением
  `Table = off`, бэкапом и откатом, если handshake не появился за 25 с.
- Ручной запуск инкрементального обновления RU-маршрутов (добавляются только
  новые сети, удаляются только исчезнувшие) и автообновление каждые 10 с
  на странице (fetch `/api/status`, `/api/peers`, `/api/ru`).

Подробности — в `docs/OPERATIONS.md`.

## Безопасность

- Панель слушает только локальную сеть (по умолчанию `0.0.0.0:51821`); не
  публикуйте порт в интернет.
- Пароль хранится в файле `web.pass` с правами `600`, а не в юните.
- TLS — самоподписанный сертификат; браузер попросит принять исключение.
- Секреты (`web.pass`, `certs/server.key`, `awg*.conf`, клиентские `.conf`)
  не коммитьте в git. В репозитории только шаблоны.
- Для доступа снаружи используйте VPN, а не проброс порта панели.

- Debian 13 (trixie), Raspberry Pi 4, kernel `6.18.50+rpt-rpi-v8`.
- `amneziawg` / `amneziawg-tools` `1.0.20210914` (Amnezia PPA, noble).
- `python3` 3.13.5, `python3-flask` 3.1.1, `gunicorn` 23.0.0.
- `qrencode` 4.1.1, `iptables-persistent` 1.0.23, `nftables` 1.1.3.

Регресс панели: 58 проверок (auth, CSRF, заголовки, API, CRUD клиента,
QR/ZIP, карточки, RU, конкурентность, rate-limit) — все зелёные.
После исправления `detect_internal()` дополнительно: `verify.sh` 25/25,
создание/удаление тестового клиента (локальный endpoint = `192.168.89.245`),
число пиров и клиентских файлов восстановлено.
После правок авторизации и RU-скрипта: иконки `/favicon.ico` и
`/apple-touch-icon*` → `204` без `WWW-Authenticate`; инкрементальное
обновление RU — второй запуск `added 0, removed 0` за 1–2 с, полная
перестройка таблицы не выполняется.
