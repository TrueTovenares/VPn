# Ручная установка AWG Router с нуля

Пошаговая инструкция для чистой **Debian 13 (trixie) arm64** на Raspberry Pi 4.
Все команды выполняются от пользователя с `sudo` (в примерах — `pavelilyushin`).

> **Внимание.** Установка меняет сетевую конфигурацию. Если вы подключены к
> роутеру по SSH, не меняйте маршрут по умолчанию и не включайте
> `Table = off`/`Table = auto` необдуманно: можно потерять доступ.
> Делайте бэкапы конфигов перед правками.

---

## 0. Переменные

Вынесите параметры своей сети в переменные — дальше они используются в командах.

```bash
# Сеть и адреса
export LAN_IF=eth0
export LAN_GW=192.168.89.1
export LAN_NET=192.168.89.0/24
export ROUTER_IP=192.168.89.245

# VPN
export AWG_PORT=51820
export AWG_SUBNET=10.8.0.0/24
export AWG_SERVER_IP=10.8.0.1/24

# Панель
export PANEL_PORT=51821
export PANEL_USER=pavelilyushin
export PANEL_DIR=/home/pavelilyushin/awg-migration/web

# RU-маршруты
export RU_TABLE=100
export RU_TABLE_NAME=awg_foreign
```

Проверьте, что `ip -4 addr show "$LAN_IF"` содержит `$ROUTER_IP`, а
`ip route show default` указывает на `$LAN_GW`.

## 3. Установка AmneziaWG

AmneziaWG — форк WireGuard с обфускацией. В этой инсталляции используется
**Amnezia PPA** (Ubuntu `noble`) на Debian 13. Это не официальная поддержка
Debian, но пакеты работают; версия `1.0.20210914`.

### 3.1. Ключ и репозиторий

```bash
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL "https://keyserver.ubuntu.com/pks/lookup?op=get&search=0x4166F2C257290828" \
  | sudo gpg --dearmor -o /etc/apt/keyrings/amnezia-ppa.gpg
sudo chmod 0644 /etc/apt/keyrings/amnezia-ppa.gpg

sudo tee /etc/apt/sources.list.d/amnezia-ppa.sources >/dev/null <<'EOF'
Types: deb
URIs: https://ppa.launchpadcontent.net/amnezia/ppa/ubuntu
Suites: noble
Components: main
Signed-By: /etc/apt/keyrings/amnezia-ppa.gpg
EOF
```

Отпечаток ключа для проверки:

```
75C9 DD72 C799 870E 3105  42E2 4166 F2C2 5729 0828
uid: Launchpad PPA for Iurii Egorov
```

> Альтернатива: официальный установщик
> `https://github.com/bivlked/amneziawg-installer` (`install_amneziawg.sh`)
> сам добавляет PPA, DKMS-модуль, sysctl и apt-хук. Ниже описаны те же шаги
> вручную.

### 3.2. Пакеты и модуль

```bash
sudo apt update
sudo apt install -y amneziawg amneziawg-tools amneziawg-dkms
sudo modprobe amneziawg
lsmod | grep amneziawg
awg --version
```

Ожидается `amneziawg-tools v3.1.20260812` (или новее) и строка `amneziawg`
в `lsmod`.

Если DKMS не собрался:

```bash
sudo dkms status
sudo dkms autoinstall
sudo modprobe amneziawg
```

### 3.3. Пересборка после обновления ядра

Скопируйте из репозитория:

```bash
sudo install -m 0755 scripts/amneziawg-ensure-module /usr/local/sbin/amneziawg-ensure-module
sudo install -m 0644 systemd/amneziawg-ensure-module.service /etc/systemd/system/
```

Apt-хук и logrotate:

```bash
sudo tee /etc/apt/apt.conf.d/99-amneziawg-post-kernel >/dev/null <<'EOF'
// amneziawg-installer (v5.12.0+): rebuild DKMS module after kernel upgrades.
// Generated by install_amneziawg.sh — do not edit; re-run the installer to refresh.
DPkg::Post-Invoke {"if [ -x /usr/local/sbin/amneziawg-ensure-module ]; then /usr/local/sbin/amneziawg-ensure-module --hook >>/var/log/amneziawg-ensure-module.log 2>&1 || true; fi";};
EOF

sudo tee /etc/logrotate.d/amneziawg-ensure-module >/dev/null <<'EOF'
/var/log/amneziawg-ensure-module.log {
    weekly
    rotate 4
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
}
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now amneziawg-ensure-module.service
```

## 5. Интерфейсы AmneziaWG

### 5.1. Каталоги и права

```bash
sudo install -d -m 0750 -o root -g "$PANEL_USER" /etc/amnezia/amneziawg
sudo install -d -m 0700 -o "$PANEL_USER" -g "$PANEL_USER" /etc/amnezia/amneziawg/clients
```

### 5.2. Серверный интерфейс `awg0`

Сгенерируйте ключ сервера и создайте конфиг:

```bash
umask 077
PRIV=$(awg genkey)
sudo tee /etc/amnezia/amneziawg/awg0.conf >/dev/null <<EOF
[Interface]
Address = ${AWG_SERVER_IP}
ListenPort = ${AWG_PORT}
PrivateKey = ${PRIV}
MTU = 1280
EOF
unset PRIV

sudo chmod 600 /etc/amnezia/amneziawg/awg0.conf
sudo chown root:root /etc/amnezia/amneziawg/awg0.conf
```

Пиры в `awg0.conf` добавляет панель. Формат пира:

```ini
# Name = iPhone_Pavel
[Peer]
PublicKey = <публичный ключ клиента>
AllowedIPs = 10.8.0.3/32
```

> На `awg0` **не** ставьте `Table = off`: awg-quick должен добавить маршрут
> на `10.8.0.0/24`.

### 5.3. Upstream-интерфейс `awg1`

Вставьте полный конфиг от VPN-провайдера (Amnezia/WireGuard). Обязательно
добавьте `Table = off` — иначе awg-quick заменит маршрут по умолчанию и
сломает доступ в LAN/SSH.

```bash
sudo tee /etc/amnezia/amneziawg/awg1.conf >/dev/null <<'EOF'
[Interface]
Table = off
Address = <ADDRESS_ОТ_ПРОВАЙДЕРА>/32
PrivateKey = <PRIVATE_KEY_ОТ_ПРОВАЙДЕРА>
DNS = 1.1.1.1
Jc = 3
Jmin = 50
Jmax = 100
S1 = 41
S2 = 30
S3 = 15
S4 = 7
H1 = <...>
H2 = <...>
H3 = <...>
H4 = <...>
i1 = <...>

[Peer]
PublicKey = <PUBLIC_KEY_ПРОВАЙДЕРА>
AllowedIPs = 0.0.0.0/0
Endpoint = <HOST>:<PORT>
PersistentKeepalive = 27
EOF

sudo chmod 600 /etc/amnezia/amneziawg/awg1.conf
sudo chown root:root /etc/amnezia/amneziawg/awg1.conf
```

Параметры `Jc/Jmin/Jmax/S1–S4/H1–H4/i1` выдаёт провайдер вместе с ключами.
Если провайдер их не использует, оставьте только стандартные поля.

Шаблоны: `config/awg0.conf.example`, `config/awg1.conf.example`.

### 5.4. Запуск

```bash
sudo systemctl enable --now awg-quick@awg1
sudo systemctl enable --now awg-quick@awg0
sudo systemctl status awg-quick@awg0 awg-quick@awg1 --no-pager
awg show
```

`awg1` поднимайте первым, чтобы upstream был готов к моменту маршрутизации.

## 6. Маршрутизация и NAT

### 6.1. Именованная таблица

```bash
grep -q "awg_foreign" /etc/iproute2/rt_tables || \
  echo "100 awg_foreign" | sudo tee -a /etc/iproute2/rt_tables
```

### 6.2. Policy-rules и маршруты

```bash
sudo install -m 0644 systemd/awg-rules.service /etc/systemd/system/awg-rules.service
sudo systemctl daemon-reload
sudo systemctl enable --now awg-rules.service
```

Юнит делает:

```sh
ip rule add from 10.8.0.0/24 lookup awg_foreign priority 400
ip route replace default dev awg1 table 100
ip route replace 1.1.1.1/32 dev awg1
ip route replace 8.8.8.8/32 dev awg1
ip route replace 77.88.8.8/32 via 192.168.89.1 dev eth0
```

> В `systemd/awg-rules.service` жёстко зашиты `10.8.0.0/24`, `awg1` и `eth0`.
> Если у вас другие имена интерфейсов или подсеть — отредактируйте `ExecStart`
> перед установкой.

- `default dev awg1` в таблице 100 — весь клиентский трафик в VPN.
- RU-маршруты (шаг 7) добавляются в ту же таблицу через LAN-шлюз.
- `sleep 5` в юните — чтобы интерфейсы успели подняться после загрузки.
- `awg-rules` зависит от `awg-quick@awg0/awg1` через `After=`/`Wants=`.

Проверка:

```bash
ip rule show | grep 400
ip route show table 100 | head
```

### 6.3. NAT

```bash
sudo iptables -t nat -A POSTROUTING -s "$AWG_SUBNET" -o "$LAN_IF" -j MASQUERADE
sudo iptables -t nat -A POSTROUTING -s "$AWG_SUBNET" -o awg1 -j MASQUERADE

sudo iptables -t mangle -A FORWARD -o awg1 -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --set-mss 1240
sudo iptables -t mangle -A FORWARD -i awg1 -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --set-mss 1240

sudo netfilter-persistent save
```

> `-A` добавляет правило. Если запустить блок повторно, появятся дубликаты.
> Проверяйте `iptables -t nat -S POSTROUTING` и при необходимости удаляйте
> лишние через `-D` (или сразу используйте `-C` перед `-A`).

Готовый пример — `config/rules.v4.example`. Правила сохраняются в
`/etc/iptables/rules.v4` и восстанавливаются `netfilter-persistent.service`
при загрузке.

Проверка:

```bash
sudo iptables -t nat -S POSTROUTING
sudo iptables -t mangle -S FORWARD
```

> В этой инсталляции `ufw` не установлен; фильтрация — через
> `iptables-persistent` (политика `ACCEPT`, NAT и MSS сохраняются в
> `/etc/iptables/rules.v4`). Если вы включаете ufw, добавьте NAT
> в `/etc/ufw/before.rules` и разрешите forward; иначе клиенты останутся без
> интернета.

## 7. RU-маршруты

```bash
sudo install -m 0755 scripts/update-ru-routes.sh /usr/local/bin/update-ru-routes.sh
sudo /usr/local/bin/update-ru-routes.sh
tail -5 /var/log/ru-routes-update.log
ip route show table 100 | wc -l
```

Скрипт скачивает `https://www.ipdeny.com/ipblocks/data/aggregated/ru-aggregated.zone`,
сравнивает список с текущими маршрутами `via 192.168.89.1` в таблице 100 и
применяет **только разницу**: добавляет новые сети, удаляет исчезнувшие,
неизменённые не трогает. Поэтому нет окна, когда RU-трафик уходит через VPN.

Первый запуск на чистой системе добавляет все ~8.6 тыс. сетей (десятки секунд).
Повторный — обычно 0–десятки изменений и занимает 1–3 секунды; в логе видно
`Added N RU routes, removed M, unchanged K`.

Cron (от root):

```bash
sudo crontab -e
```

```cron
0 4 * * * flock -n /run/update-ru-routes.lock /usr/local/bin/update-ru-routes.sh >/dev/null 2>&1
```

`flock` защищает от одновременного запуска с кнопкой в панели (панель тоже
использует `/run/update-ru-routes.lock`).

> В `scripts/update-ru-routes.sh` значения по умолчанию:
> `GATEWAY=192.168.89.1`, `WAN_IF=eth0`, `TABLE=100`,
> `RU_LIST=/tmp/ru-aggregated.zone`. Их можно переопределить переменными
> окружения, не правя скрипт. `RU_URL` позволяет подменить источник списка
> (например, для теста через `file://`).

## 8. Веб-панель

### 8.1. Каталог и исходник

```bash
sudo install -d -m 0700 -o "$PANEL_USER" -g "$PANEL_USER" "$PANEL_DIR"
sudo install -m 0600 -o "$PANEL_USER" -g "$PANEL_USER" panel/app.py "$PANEL_DIR/app.py"
```

### 8.2. Пароль

```bash
printf '%s\n' 'ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ' | sudo tee "$PANEL_DIR/web.pass" >/dev/null
sudo chown "$PANEL_USER:$PANEL_USER" "$PANEL_DIR/web.pass"
sudo chmod 600 "$PANEL_DIR/web.pass"
```

Пароль читается из `WEB_PASSWORD_FILE` (см. юнит). Альтернатива — переменная
`WEB_PASSWORD`, но файл безопаснее: пароль не виден в `systemctl show`.

### 8.3. TLS-сертификат

```bash
sudo install -d -m 0755 -o "$PANEL_USER" -g "$PANEL_USER" "$PANEL_DIR/certs"
cd "$PANEL_DIR/certs"
sudo openssl req -x509 -newkey rsa:4096 -nodes -days 3650 \
  -keyout server.key -out server.crt \
  -subj "/CN=awg-router" \
  -addext "subjectAltName=IP:${ROUTER_IP},DNS:awg-router.local"
sudo chown "$PANEL_USER:$PANEL_USER" server.key server.crt
sudo chmod 600 server.key
sudo chmod 644 server.crt
cd -
```

Сертификат самоподписанный, срок 10 лет. Браузер покажет предупреждение —
это нормально для локальной панели.

### 8.4. Юнит и запуск

```bash
sudo install -m 0644 systemd/awg-web.service /etc/systemd/system/awg-web.service
sudo systemctl daemon-reload
sudo systemctl enable --now awg-web.service
sudo systemctl status awg-web.service --no-pager
```

> В юните жёстко указаны `/home/pavelilyushin/awg-migration/web` и
> `WEB_USER=pavelilyushin`. Если используете другого пользователя или каталог,
> замените пути и логин в `systemd/awg-web.service` перед установкой.

Юнит запускает **gunicorn**:

- `--workers 1 --threads 8 --worker-class gthread` — состояние (`rate-limit`,
  кэш MAC, статус RU) живёт в памяти одного процесса; несколько worker'ов
  сломали бы rate-limit и продублировали фоновый поток.
- TLS — напрямую, без reverse-proxy.
- `--timeout 180` — сохранение upstream может занимать до ~60 с.
- `Server: gunicorn` без версии Python/Werkzeug.

Проверка:

```bash
curl -sk -o /dev/null -w '%{http_code}\n' https://127.0.0.1:${PANEL_PORT}/          # 401
curl -sk -u "$PANEL_USER:ПАРОЛЬ" -o /dev/null -w '%{http_code}\n' \
  https://127.0.0.1:${PANEL_PORT}/                                                  # 200
```

### 8.5. Firewall (опционально)

Если ufw активен:

```bash
sudo ufw allow from "$LAN_NET" to any port "$PANEL_PORT" proto tcp
sudo ufw allow "$AWG_PORT"/udp
```

Порт панели не публикуйте в интернет.

### 8.6. Константы `app.py`

Если ваша сеть отличается от `192.168.89.0/24`, поправьте в `panel/app.py`:

| Константа | Значение по умолчанию | Комментарий |
|---|---|---|
| `CONFIG_DIR` | `/etc/amnezia/amneziawg` | каталог конфигов |
| `AWG_CONF` | `.../awg0.conf` | серверный интерфейс |
| `AWG1_CONF` | `.../awg1.conf` | upstream |
| `CLIENTS_DIR` | `.../clients` | клиентские `.conf` |
| `RU_TABLE` | `100` | таблица RU-маршрутов |
| `RU_GATEWAY` | `192.168.89.1` | LAN-шлюз |
| `RU_LIST_FILE` | `/tmp/ru-aggregated.zone` | скачанный список |
| `RU_LOG` | `/var/log/ru-routes-update.log` | лог |
| `RU_SCRIPT` | `/usr/local/bin/update-ru-routes.sh` | скрипт |
| `PEER_INFO_FILE` | `/var/lib/awg-web/peer-info.json` | кэш MAC |
| `EXT_IP_CACHE_FILE` | `/var/lib/awg-web/last-external-ip` | последний внешний IP |
| `HS_OK_AGE` / `HS_ERR_AGE` | `180` / `86400` | пороги цвета handshake |
| `IFACE_SERVICES` | `awg-quick@awg0/awg1` | юниты интерфейсов |
| `next_ip()` | `10.8.0.2–254` | подсеть клиентов |
| `detect_external()` | `ifconfig.me`, кэш 60 с | внешний IP для конфига |
| `detect_internal()` | LAN IP (`192.168.89.245`) | адрес для локального конфига; адреса `awg0`/`awg1` исключаются |

> `detect_internal()` важен: при policy-routing `ip route get 1.1.1.1` может
> вернуть `src 10.71.107.82` (адрес `awg1`). Такой адрес нельзя выдавать
> клиенту как локальный endpoint — до туннеля клиент ещё не подключён.
> Функция отбрасывает адреса туннелей и берёт адрес LAN-интерфейса.
> Переопределить можно переменной `INTERNAL_ENDPOINT` (например,
> `INTERNAL_ENDPOINT=192.168.89.245`).

Переменные окружения панели: `WEB_PORT` (51821), `WEB_BIND` (0.0.0.0),
`WEB_USER`, `WEB_PASSWORD`/`WEB_PASSWORD_FILE`, `WEB_TLS_CERT`, `WEB_TLS_KEY`,
`AWG_LISTEN_PORT`, `EXTERNAL_ENDPOINT`, `INTERNAL_ENDPOINT`.

## 10. Первый клиент

1. Откройте `https://<ROUTER_IP>:51821`, введите логин/пароль.
2. Нажмите **«+ Создать клиента»**.
3. Переименуйте пира (карандаш) в понятное имя.
4. Нажмите **QR** — откроются два кода: внешний и локальный.
5. Или **`.conf ×2`** — скачается ZIP с `<имя>.conf` и `<имя>-local.conf`.
6. Импортируйте конфиг в AmneziaWG/WireGuard-клиент.
7. Через 10–30 секунд в таблице появится handshake и трафик.

Внешний конфиг использует внешний IP (для подключения из интернета),
локальный — адрес в LAN (для подключения дома). Если внешний IP динамический,
панель кэширует последний известный и обновляет его раз в 60 секунд.

## 11. Откат и удаление

Перед изменениями сохраните:

```bash
sudo tar czf /root/awg-router-backup-$(date +%F).tgz \
  /etc/amnezia/amneziawg \
  /etc/systemd/system/awg-web.service \
  /etc/systemd/system/awg-rules.service \
  /etc/systemd/system/amneziawg-ensure-module.service \
  /etc/iptables/rules.v4 \
  /etc/sysctl.d/99-amneziawg-security.conf \
  /usr/local/bin/update-ru-routes.sh \
  /home/pavelilyushin/awg-migration/web/app.py \
  /home/pavelilyushin/awg-migration/web/web.pass \
  /home/pavelilyushin/awg-migration/web/certs
```

Остановка:

```bash
sudo systemctl disable --now awg-web.service awg-rules.service
sudo systemctl disable --now awg-quick@awg0 awg-quick@awg1
```

Удаление правил:

```bash
sudo ip rule del from 10.8.0.0/24 lookup awg_foreign priority 400 2>/dev/null || true
sudo iptables -t nat -D POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE 2>/dev/null || true
sudo iptables -t nat -D POSTROUTING -s 10.8.0.0/24 -o awg1 -j MASQUERADE 2>/dev/null || true
sudo netfilter-persistent save
```

> Не удаляйте `awg1`, пока не убедились, что доступ к роутеру не зависит от
> VPN. В этой схеме SSH идёт через `eth0`, но проверьте `ip route` перед
> изменениями.
